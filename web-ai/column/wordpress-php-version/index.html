WordPress（ワードプレス）で会社のホームページを運営していると、管理画面に「PHPの更新が必要です」という表示が出たり、レンタルサーバー会社から「PHPのバージョンを切り替えてください」というお知らせが届いたりすることがあります。2026年10月には、PHPに重大な脆弱性（セキュリティ上の弱いところ）が見つかり、ニュースでも大きく取り上げられました。

「PHPとは何か」「うちのサイトは何を使っているのか」「切り替えたら壊れないか」。この記事では、WordPressとPHPの関係から、バージョンを新しく保つ理由、確かめ方、安全に更新する手順、うまくいかなかったときの戻し方までを、専門家でない担当者の方にも分かるように、制作する側の目線でまとめます。

PHPとWordPressの関係

PHPは、Webサイトの裏側で動くプログラミング言語です。WordPressは、このPHPで作られています。ページを開いた人がいると、サーバーの上でPHPが動き、データベースに入っているお知らせや会社情報を取り出して、ページの形に組み立てて返します。

建物にたとえると、WordPressが「家の間取りや設備」、PHPが「その家を動かす電気や水道の仕組み」です。WordPress本体やプラグイン（あとから足す機能）、テーマ（デザインのひな形）は、どれもPHPの上で動いています。そのため、PHPのバージョンが変わると、その上で動くものすべてに影響が出る可能性があります。

大事なのは、PHPはWordPressの中ではなく、サーバーに入っているという点です。WordPressの管理画面で「更新」ボタンを押しても、PHPは新しくなりません。PHPのバージョンは、契約しているレンタルサーバーの設定で決まり、多くの場合はサーバーの管理画面から切り替えます。WordPressそのものの仕組みは、ホームページにWordPressは必要かで紹介しています。

なお、ホームページを見る側のスマホやパソコンでは、PHPは動いていません。PHPの更新が必要なのは、ホームページを公開している側だけです。

PHPのバージョンを新しく保つ理由

WordPressの公式サイトは、PHPを新しく保つ利点として、サイトが速くなることと、安全になることを挙げています。中小企業の会社サイトにとっては、次の3つが大きな理由です。

1. セキュリティ（安全のため）

PHPに弱いところが見つかると、開発元は修正版を出します。ただし、修正版が出るのはサポート期間の中にある版だけです。サポートが終わった古いPHPには、弱いところが見つかっても修正は出ません。古いまま使い続けると、外からの攻撃に対して無防備な状態が続きます。

2. 速さ

WordPressの公式サイトは、PHPは新しいバージョンになるたびに効率が良くなると説明しています。ページの表示が速くなると、訪れた人が途中で離れにくくなります。

3. サポート期間

PHPには、版ごとに決まったサポート期間があります。PHP公式サイトの説明では、新しい版が出てから2年間は不具合とセキュリティの修正が行われ（アクティブサポート）、その後の2年間はセキュリティの修正だけが行われます。合わせて4年が過ぎると、サポートが終わります。

PHPのサポート状況（2026年10月22日時点）

PHP公式サイトの「Supported Versions」のページで、2026年10月22日に確かめた、サポートが続いている版は次のとおりです。

PHPの系統公開日アクティブサポートセキュリティサポートの終了
8.52025年11月20日2027年12月31日まで2029年12月31日
8.42024年11月21日2026年12月31日まで2028年12月31日
8.32023年11月23日終了（セキュリティ修正のみ）2027年12月31日
8.22022年12月8日終了（セキュリティ修正のみ）2026年12月31日

この表にない8.1以前の版は、すでにサポートが終わっています。また、8.2も2026年12月31日でサポートが終わる予定です。いま8.2を使っているサイトは、年内に次の版へ移す準備を始めるのがおすすめです。サポート状況は年ごとに変わるので、更新を考えるときはPHP公式サイトで最新の内容を確かめてください。

2026年10月の脆弱性（PHP2Shell）と修正版

2026年10月21日、PHPを開発するPHP Groupは、重大な脆弱性（CVE-2026-109618、CVE-2026-109619、通称PHP2Shell）を直す修正版を公開しました。JPCERT/CCは、悪用されると、PHPが動いているサーバーの権限で、外から好きなプログラムを動かされるおそれがあると説明しています。

PHPの系統修正版
8.5系8.5.12
8.4系8.4.27
8.3系8.3.36
8.2系8.2.35
8.1系以前修正版は出ない（サポートが続く版への移行が必要）

ここで分かるのは、サポートが続いている版を使っていれば、修正版を当てるだけで対応できるということです。反対に、8.1以前の古い版を使っていると、修正版がないため、版そのものを切り替えるしかありません。日ごろからPHPを新しく保っておくことが、いざというときの備えになります。何が起きたのかと、自社サイトの確かめ方は、PHPの脆弱性（PHP2Shell）とは？自社サイトの確かめ方と対応でくわしくまとめています。

なお、同じ系統の中の小さな更新（8.3.35から8.3.36など）と、系統をまたぐ切り替え（8.1から8.3など）は、別のものです。小さな更新をサーバー会社が当てるのか、利用者が管理画面で選ぶのかは、サーバーによって違います。自社のサーバーがどちらなのかは、サーバー会社のお知らせや管理画面で確かめてください。

WordPressが推奨するPHPのバージョン

WordPressの公式サイトの「Requirements（動かすための条件）」のページでは、2026年10月22日時点で、次のように案内されています。

項目推奨
PHP8.3以上
データベースMySQL 8.0以上、またはMariaDB 10.11以上
通信HTTPS（暗号化された通信）に対応していること

同じページには、WordPressはPHP 7.4以上でも動くものの、それらの版は公式のサポートが終わっており、サイトがセキュリティ上の弱いところにさらされるおそれがあるとも書かれています。つまり「動く」ことと「安全に使える」ことは別だということです。目安としては、WordPressの推奨である8.3以上で、かつPHP公式のサポートが続いている版を選ぶのが安心です。

いまのPHPのバージョンを確かめる方法

まずは、自社のサイトがどの版で動いているかを確かめます。方法は2つあります。

WordPressの管理画面で確かめる

  1. WordPressの管理画面にログインする
  2. 左のメニューから「ツール」→「サイトヘルス」を開く
  3. 上の「情報」タブを開く
  4. 「サーバー」の項目を開き、「PHPのバージョン」を見る

WordPressの公式サイトは、ここに表示される数字が推奨の8.3以上なら、いまは更新の必要はないと案内しています。推奨より古い場合は、管理画面のダッシュボードやサイトヘルスに「PHPの更新が必要」「PHPの更新を推奨」といった表示が出ることがあります。これは、更新を考えるきっかけとして受け止めてください。

あわせて、同じ「情報」タブで、WordPress本体のバージョンや、使っているプラグイン、テーマの一覧も見られます。あとで制作会社に相談するときにも役立つので、画面を保存しておくと便利です。

レンタルサーバーの管理画面で確かめる

契約しているレンタルサーバーの管理画面にも、PHPのバージョンを見たり切り替えたりする画面があります。名前は「PHPバージョン設定」「PHPの設定」など、会社によって違います。ひとつのサーバー契約で複数のサイトやドメインを運営している場合は、サイトごとに版が違うこともあるので、すべて確かめます。

管理画面にログインできない、どこと契約しているか分からない、という場合は、まずその状態を解消するのが先です。サーバーやドメインの契約の基本は、ドメインとサーバーとは？でまとめています。

PHPのバージョンを安全に上げる手順

WordPressの公式サイトも、PHPの更新はふつうは問題なく済むものの、テーマやプラグインが新しい版で動くかは保証できないと説明しています。そのため、いきなり切り替えるのではなく、次の順番で進めます。

順番やることねらい
1バックアップを取る何かあったときに、いまの正常な状態へ戻せるようにする
2WordPress本体・プラグイン・テーマを更新する新しいPHPに合わせた修正を先に取り込む
3テスト環境があれば、先に試す本番のサイトを止めずに、不具合を見つける
4PHPのバージョンを切り替えるサーバーの管理画面で、新しい版を選ぶ
5表示と動きを確かめるページ、フォーム、管理画面に異常がないかを見る

1. バックアップを取る

サイトのファイルと、データベース（お知らせや設定が入っている場所）の両方を保存します。レンタルサーバーに自動バックアップの機能があれば、いつの分まで戻せるかも確かめておきます。バックアップがあるかどうかで、失敗したときの安心感が大きく変わります。

2. 本体・プラグイン・テーマを更新する

管理画面の「ダッシュボード」→「更新」から、WordPress本体、プラグイン、テーマを新しくします。プラグインやテーマの作り手は、新しいPHPで動くように修正を出していることが多いため、PHPより先にこちらを新しくしておきます。更新したら、いったんサイトがいつもどおり動いているかを確かめます。

3. テスト環境があれば先に試す

サーバーによっては、本番のサイトを複製した「テスト環境（ステージング）」を作れます。そこでPHPを切り替えて問題がなければ、本番でも同じように進めます。テスト環境がない場合は、アクセスの少ない時間帯を選び、すぐ戻せる準備をしてから進めます。

4. PHPのバージョンを切り替える

レンタルサーバーの管理画面で、新しい版を選んで保存します。いきなり何段も飛ばすのが不安な場合は、ひとつずつ上げて、その都度確かめる進め方もあります。

5. 表示と動きを確かめる

切り替えたら、次の点を確かめます。

  • トップページと主なページが、いつもどおり表示されるか
  • お問い合わせフォームから送信でき、メールが届くか
  • 管理画面にログインでき、お知らせの投稿や編集ができるか
  • スマホで見ても崩れていないか
  • サイトヘルスで、PHPのバージョンが新しくなっているか

とくにお問い合わせフォームは、見た目が正常でも送信だけできなくなっていることがあります。実際に送ってみて、届くところまで確かめるのが確実です。

表示が崩れた・真っ白になったときの戻し方

切り替えたあとに、ページの表示が崩れた、画面が真っ白になった、「このサイトで重大なエラーが発生しました」と出た、という場合は、慌てずに次の順番で戻します。

  1. PHPのバージョンを元に戻す：サーバーの管理画面で、切り替える前の版を選び直します。多くの場合、これで元の表示に戻ります。
  2. それでも戻らなければバックアップから戻す：WordPressの公式サイトも、まずPHPの版を戻し、そのうえで取っておいたバックアップで元に戻す流れを案内しています。
  3. 原因を調べる：どのプラグインやテーマが新しい版に合っていないのかを調べ、更新する、別のものに替える、などの対応を決めてから、もう一度切り替えます。

WordPressには、重大なエラーが起きたときに、管理者のメールアドレスへ知らせが届く仕組みもあります。届いたメールには、原因になったプラグインやテーマの名前が書かれていることがあるので、捨てずに確かめてください。

ただし、古いPHPに戻すのは一時しのぎです。戻した版がサポート切れなら、弱いところは残ったままです。原因を直して、できるだけ早く新しい版へ移すことが大切です。

更新できない古いプラグインがあるときの考え方

長く使っているサイトでは、新しいPHPで動かないプラグインやテーマが見つかることがあります。作り手が更新をやめていて、修正が出ない場合もあります。そのときは、次のように考えます。

状況考え方
作り手が更新を続けている作り手の更新を待つか、問い合わせる。対応が出たら更新してから切り替える
更新が止まっていて、代わりのものがある同じ働きをする、更新が続いているプラグインに置きかえる
実はもう使っていない停止して削除する。使っていないプラグインも、弱いところの入り口になりうる
独自に作った機能で、作った会社に連絡がつかない中身を直せる会社に相談する。直すより作り直す方が早いこともある

「そのプラグインのために、古いPHPを使い続ける」という選択は、おすすめしません。ひとつの古い部品のために、サイト全体を危ない状態に置くことになるからです。ほかにも古いところが多く、直すたびに別の不具合が出るような状態なら、作り直しや、ほかの作り方への移行を考える時期かもしれません。WordPressのほかの守り方はWordPressのセキュリティ対策で、別の仕組みへの移り方はWordPressから乗り換えるには？乗り換え先の比べ方と移行の手順でまとめています。

制作会社に頼むときに伝えること

自社で進めるのが難しい場合は、制作会社や保守を頼んでいる会社に相談します。次のことを伝えると、話が早く進みます。

  • サイトのアドレスと、契約しているレンタルサーバーの会社名
  • サイトヘルスで確かめた、いまのPHPとWordPressのバージョン
  • 使っているプラグインとテーマの一覧（サイトヘルスの「情報」タブの画面でもかまいません）
  • お問い合わせフォームなど、とくに止まると困る機能
  • サーバーやWordPressの管理画面に、誰がログインできるか
  • いつまでに終えたいか（サポート終了の時期や、サーバー会社の切り替え期限）

あわせて、作業の前にバックアップを取るか、テスト環境で試すか、うまくいかなかったときにどう戻すか、作業後に何を確かめるか、費用はいくらか、を聞いておくと安心です。PHPの更新は一度きりではなく、数年ごとにやってくる作業です。毎月の保守の中に含まれているのかどうかも、確かめておきましょう。保守や管理にかかる費用の考え方は、ホームページの維持費・管理費の相場で紹介しています。

マツケンスタジオでは、ドメインとサーバーはお客様の名義のまま、最初の相談から公開後まで同じ担当が対応します。公開後の更新や改善も続けられ、社内での更新が難しい場合は、月額サポートで代わりに更新することもできます。

まとめ

WordPressはPHPの上で動いており、PHPのバージョンはWordPressの中ではなくサーバーの設定で決まります。PHPには版ごとにサポート期間があり、2026年10月22日時点では8.2から8.5がサポートの中にあります。WordPressの推奨は8.3以上で、8.2は2026年12月31日でサポートが終わる予定です。

まずはサイトヘルスでいまの版を確かめ、古ければ、バックアップ、本体・プラグイン・テーマの更新、テスト、切り替え、確認の順に進めます。うまくいかなければPHPの版を戻し、原因を直してからもう一度進めます。PHP2Shellのような重大な脆弱性が見つかったときも、サポートが続く版を使っていれば、修正版を当てるだけで対応できます。日ごろから新しく保つことが、会社のホームページを守るいちばんの近道です。

よくある質問

Q
WordPressを更新すれば、PHPも新しくなりますか？

なりません。PHPはWordPressの中ではなく、サーバーに入っています。PHPのバージョンは、契約しているレンタルサーバーの管理画面で切り替えるか、サーバー会社や制作会社に依頼して変えます。

Q
いまのPHPのバージョンはどこで確かめられますか？

WordPressの管理画面で「ツール」→「サイトヘルス」→「情報」タブ→「サーバー」と進むと、PHPのバージョンが表示されます。レンタルサーバーの管理画面でも確かめられます。

Q
WordPressが推奨するPHPのバージョンはいくつですか？

2026年10月22日時点で、WordPressの公式サイトは8.3以上を推奨しています。PHP 7.4以上でも動きますが、サポートが終わった版はセキュリティ上の弱いところにさらされるおそれがあるとされています。

Q
PHPを切り替えたら、サイトが真っ白になりました。どうすればいいですか？

まずサーバーの管理画面で、切り替える前のPHPの版に戻してください。それでも戻らなければ、取っておいたバックアップで元に戻します。そのうえで、合わないプラグインやテーマを調べて直してから、もう一度切り替えます。

Q
古いプラグインが新しいPHPで動かない場合は、PHPを古いままにしてもいいですか？

おすすめしません。サポートが終わったPHPには、弱いところが見つかっても修正が出ません。代わりのプラグインに置きかえる、使っていなければ削除する、中身を直せる会社に相談する、といった対応を考えます。

Q
PHP2Shellへの対応は、どの版にすればいいですか？

PHP Groupは8.5.12、8.4.27、8.3.36、8.2.35を修正版として公開しています。8.1以前には修正版が出ないため、サポートが続いている版への切り替えが必要です。8.2は2026年12月31日でサポートが終わる予定なので、8.3以上を選ぶと安心です。
